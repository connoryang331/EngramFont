# BUG-002 · 主开关切换后依赖行禁用态不刷新

日期：2026-10-14  状态：fixed

## 现象

设置页勾选 "Use custom node colors and sizes" 后，六个颜色/尺寸行的 `disabled`
状态与灰显不变（Playwright `fill` 30s 超时，input 恒为 `disabled`）。

## 根因

两层：

1. **事件回声抑制（结构性）**：`ObservableController` 惯例——组件自己的
   `controller.setItem(key, value, this)` 会被自己的 `_modelListener` 忽略
   （`event.senderInfo === this`，Fontra 用它保护进行中的输入不被重渲染打断）。
   依赖 `nodeAppearanceCustom` 的其他行因此永远不会重渲染。旧结构没有依赖行，
   这条惯例从未暴露过问题。
2. **实现期笔误（被探测当场抓住）**：中间版本 helper 定义为 `tagDisabledTarget`
   而调用点写 `tagDisabled`，bundle 后运行时 `ReferenceError`——headless 探测脚本
   （pageerror 监听）当场定位。教训：改完先跑一次 headless 冒烟再交付。

## 修复

不走整行重渲染（会重建输入框、丢焦点），新增
`SimpleSettings.refreshDisabledStates()`：对每个带 `disabledWhen` 的行**原位**
切换 `disabled` class 与 input `disabled` 属性；checkbox 的 `onchange` 显式调用；
`_render()` 尾部也调用一次兜底。通用机制 `disabledWhen(model)` 留在渲染器里。

## 验证

Playwright：勾选后 3 个 number + 3 个 color 全部 enabled；取消后全部 disabled
（`qa/verify-settings.mjs`）。备注：总开关随后被整体移除（ADR-0002），
`disabledWhen`/`refreshDisabledStates` 作为通用能力保留。
