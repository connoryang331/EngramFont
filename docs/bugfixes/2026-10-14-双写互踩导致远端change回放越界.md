# BUG-006 · 自动化测试与用户实时会话双写互踩，远端 change 回放越界

日期：2026-10-14  状态：fixed

## 现象

用户在编辑器里正常操作（画矩形、点选节点）时，控制台连续报
`contourPointIndex out of bounds: 6 / 9`（`applyChange` 回放 `deletePoint` change 时
越界，来自 `_editGlyphAndRecordChanges` 的远端 change 应用），且画布上的节点
形状"自己变了"（方块变杏仁形——实际是自动化会话改动了 smooth 标志被回放进
用户视图）。

## 根因

**双写互踩**（EXECUTION.md 红线场景）：agent 的 headless 验证脚本
（verify-slant / verify-almond / verify-delete / verify-togglesmooth…）在用户
**正在实时使用的 8800 实例、同一个 Untitled.fontra 工程**上做无人化写操作
（删点、删 quad、切 smooth、改点类型）。Fontra 把每个会话的修改以 change
广播给同工程的其他会话——agent 会话的删点/改型 change 回放到用户会话时，
两边字形状态已经分叉，索引对不上 → 越界；用户看到的图标变化 =
agent 会话的 smooth 标志改动被回放进用户视图。

## 修复（纪律 + 隔离）

1. **agent 的任何写操作验证一律走 e2e 隔离实例**（8801 + `.e2e-fonts`，
   见 playwright.config.mjs），或先停用户的 8800 实例并征得同意；
   **禁止对用户在线实例做无人化写操作**（已写入 AGENTS.md 硬约束）。
2. 需要在真实数据上做只读检查时（截图 / 数据 dump）只读不写。

## 验证

8801 隔离实例上的删点矩阵（1 点 / 连续 / 分散 / 回绕 / 整轮廓）全部通过，
无越界；用户实例零写入。

## 备注

- 本次事故还损坏了 Untitled.fontra 的 "o" 字形（agent 的删点矩阵把它删空了）。
  原始 24 点数据已在会话记录中留存，可按需重建；用户若在自己会话里
  Ctrl+Z 也可回退 agent 广播进去的改动。
- 用户字形 f/h/i/l/n/r/v/y 的"只有 off-curve 点"是用户的 blob 字母设计
  （纯 quad 闭合轮廓），不是损坏——已核实画布渲染正常。
