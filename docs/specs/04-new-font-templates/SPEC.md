# R4 · New Font / Template Flow · Technical Spec

## 1. Architecture & Data Flow
```
landing "New Font" card (new)
  └─ POST /api/new-font (new webAPI)
      body: {name: "MyFont", template: "empty"|"latin-kernel"|"latin-full"}
      └─ [reuse] createNewFontAndPopulate(path)  (backends/populate.py, already available)
         when template != empty: append seed glyphs
      └─ validation: duplicate name → 409; sanitize path
  ← frontend redirects to editor.html?project=<name>.fontra
```

## 2. Interface Contract
```
POST /api/new-font
  body: {"name": "MyFont", "template": "latin-kernel"}
  200: {"project": "MyFont.fontra"}
  409: {"error": "name exists"}    400: {"error": "bad name|template"}
```
- name rule: `[A-Za-z0-9_-]{1,64}`; generates file `<name>.fontra` in the font directory

## 3. Template Data
| Template | Content | Source |
|---|---|---|
| empty | empty (only Regular source + lineMetrics) | available via createNewFontAndPopulate |
| latin-kernel | basic A-Z a-z 0-9 glyphs (blocky demo outlines) | generated by `scripts/make-template.py` (geometric outlines, same style as demo-liga) |
| latin-full (P2) | full common Latin set | pre-extracted from open-source fonts (OFL) |

- Template file format: isomorphic to .fontra glyphs/*.json (name/sources/layers); the generator script produces `assets/templates/latin-kernel.json` in one pass

## 4. Seed Glyph Injection
- Current populate behavior: creates a Regular source + GF Latin Kernel glyph set **references** (no outlines)
- This requirement extends it: when template=latin-kernel, call writeGlyph per glyph (putGlyph with codePoints) so glyphs are visible/editable on open (matching meshfont's "template card → glyphs right away" experience)

## 6. Error Handling Matrix
| Scenario | Behavior |
|---|---|
| duplicate name | 409 name exists |
| invalid name | 400 bad name |
| unknown template | 400 bad template |
| disk error | 500 + message |
